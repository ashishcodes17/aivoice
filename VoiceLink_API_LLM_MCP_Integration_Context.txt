# VoiceLink API — LLM / MCP Integration Context

Use this as implementation context for an AI coding agent. Do not invent undocumented endpoints, fields, error shapes, role permissions, enum values, or response fields. Where this document marks an item unresolved, ask for confirmation or make the uncertainty explicit.

Base URL: `https://app.voicelink.co.in/api/v1`
Authentication: Bearer token via `Authorization: Bearer {access_token}` for authenticated endpoints.

## Platform context
VoiceLink (a product by Elision Group) is a telephony infrastructure platform connecting voice bots to real phone networks in India through SIP Trunk and WebSocket connectivity, DID provisioning, call routing, reseller management and webhook/call-reporting workflows.

SIP:
- VoiceLink SIP domain: sip.voicelink.co.in
- VoiceLink SIP port: 3300
- Customer static IP/port and VoiceLink SIP endpoint are mutually allowlisted according to the supplied overview.

WebSocket media:
- Bidirectional WSS audio in the supplied overview is base64-encoded A-law, 8-bit, 8 kHz, mono.
- Return bot audio in the same format unless VoiceLink confirms a different media format for the deployment.
- WebSocket events: connected, start, media, mark, clear, transfer, stop
- Webhook lifecycle events: call.initiated, call.answered, call.ended, call.completed

## Integration flows
### Option A — Full Reseller Onboarding
Audience: New reseller / platform partner
Use case: Create the reseller, verify email, log in, complete KYC and inspect commercial state.
Sequence:
1. Reseller Signup — `POST /reseller/signup`
2. Verify Email OTP — `POST /auth/verify-otp`
3. Login — `POST /auth/login`
4. KYC Status — `GET /reseller/kyc/status`
5. Step 1 — Register Details — `POST /reseller/kyc/step-1-register-details`
6. Step 2 — PAN Verification — `POST /reseller/kyc/step-2-pan-verify`
7. Upload KYC Document — `POST /reseller/kyc/upload-document`
8. Step 3 — Aadhaar Initiate — `POST /reseller/kyc/step-3-aadhaar-init`
9. Step 3 — Aadhaar DigiLocker Callback — `GET /reseller/kyc/step-3-aadhaar-callback`
10. Upload KYC Document — `POST /reseller/kyc/upload-document`
11. Step 4 — GST Verification — `POST /reseller/kyc/step-4-gst-verify`
12. Upload KYC Document — `POST /reseller/kyc/upload-document`
13. Final Submit — `POST /reseller/kyc/final-submit`
14. Get Reseller Profile — `GET /reseller/profile`
Note: GST steps are business-only. In verification-link mode replace the OTP step with the emailed link.

### Option B — Provision an End Client
Audience: Reseller onboarding a customer
Use case: Create a client, allocate commercial capacity, map a DID and prepare the account for voice routing.
Sequence:
1. Login — `POST /auth/login`
2. Get Reseller Profile — `GET /reseller/profile`
3. Create Client — `POST /reseller/client/create`
4. Allocate Wallet Balance to Client — `POST /reseller/client/allocate-wallet/{client_id}`

6. Map DID to Client — `POST /reseller/client/map-did`
7. Get Reseller Clients — `GET /reseller/clients`
Note: Client verification/KYC can be performed using client_id on the KYC endpoints where supported.

### Option C — Buy DIDs & Channels
Audience: Reseller with an active direct-purchase plan
Use case: Discover DID types, select inventory, build a draft order, inspect pricing and confirm purchase.
Sequence:
1. Get Reseller Profile — `GET /reseller/profile`
2. List Active DID Types — `GET /reseller/did-types`

9. Purchased DID List — `GET /reseller/did/purchased`
Note: Add Channels and Promocode are optional. Request-required DID types use the approval path instead.

### Option D — Request a Regulated DID Series
Audience: Reseller needing request-required / DLT-regulated numbers

3. List Purchase Requests — `GET /reseller/did-purchase-request`

### Option E — SIP Voicebot Integration
Audience: Voicebot using SIP trunking

## API reference
## Authentication & User
### Login
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/login`
- Auth: Public
- Roles/context: Reseller, Client, Agent
- Purpose: Authenticate a user and return a Sanctum Bearer token.
- Parameters:
  - `username` (string, Mandatory, body): Registered username
  - `password` (string, Mandatory, body): Account password
- Rules:
  - Use Authorization: Bearer {access_token} on authenticated requests.
  - If the password is correct but email is unverified, login returns 422. In OTP mode, a verification code is emailed automatically.
  - An incorrect password does not trigger a verification email.
  - After OTP verification, call login again; verify-otp does not return a token.
- Request example:
```
{"password":"Secret@123","username":"johndoe"}
```
- Response example:
```
{"data":{"user":{"id":10,"name":"John Doe","email":"john@acme.com","username":"johndoe"},"token_type":"Bearer","access_token":"1|abc123..."},"status":true,"message":"Login successful."}
```

### Logout
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/logout`
- Auth: Bearer
- Roles/context: All authenticated roles
- Purpose: Revoke the current Sanctum Bearer token.
- Rules:
  - The current token is permanently invalidated and cannot be reused.
- Response example:
```
{"data":[],"status":true,"message":"Logged out successfully."}
```

### Forgot Password
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/forgot-password`
- Auth: Public
- Roles/context: All user roles
- Purpose: Send a password reset link to the registered email address.
- Parameters:
  - `email` (string, Mandatory, body): Registered email address
- Request example:
```
{"email":"john@acme.com"}
```
- Response example:
```
{"data":[],"status":true,"message":"Password reset link sent. Please check your email."}
```

### Reset Password
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/reset-password`
- Auth: Public
- Roles/context: All user roles
- Purpose: Reset the account password using the token received by email.
- Parameters:
  - `token` (string, Mandatory, body): Password reset token from the email
  - `email` (string, Mandatory, body): Registered email address
  - `password` (string, Mandatory, body): New password
  - `password_confirmation` (string, Mandatory, body): Must match password
- Rules:
  - All active Sanctum tokens are revoked after a successful reset.
  - Call login again to obtain a fresh token.
- Request example:
```
{"email":"john@acme.com","token":"abc123xyz...","password":"NewSecret@123","password_confirmation":"NewSecret@123"}
```
- Response example:
```
{"data":[],"status":true,"message":"Password has been reset successfully. Please log in with your new password."}
```

### Verify Email OTP
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/verify-otp`
- Auth: Public
- Roles/context: Unverified accounts in OTP mode
- Purpose: Confirm an email address with the one-time passcode sent at signup or after a correct-password login attempt.
- Parameters:
  - `username` (string, Mandatory, body): Registered username
  - `otp` (string, Mandatory, body): 6-digit code from the verification email
- Rules:
  - Available only when project.email_verification.method = 2 (OTP mode).
  - Under verification-link mode this returns 422 and the emailed link must be used.
  - No Bearer token is returned; OTP proves inbox ownership, not login.
  - Default expiry is 10 minutes (project.email_verification.otp.expiry_minutes).
  - Default maximum incorrect attempts is 5; after that request a new code with resend-otp.
- Request example:
```
{"otp":"482913","username":"johndoe"}
```
- Response example:
```
{"data":[],"status":true,"message":"Your email address has been verified. You can now log in."}
```

### Resend Email OTP
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/auth/resend-otp`
- Auth: Public
- Roles/context: Unverified accounts in OTP mode
- Purpose: Email a fresh verification passcode.
- Parameters:
  - `username` (string, Mandatory, body): Registered username
- Rules:
  - Every resend issues a different code and invalidates the previous outstanding code.
  - Default resend cooldown is 60 seconds; requests inside the cooldown return 422 with remaining seconds.
  - Available only when project.email_verification.method = 2.
- Request example:
```
{"username":"johndoe"}
```
- Response example:
```
{"data":[],"status":true,"message":"A verification code has been sent to your email address."}
```

- Roles/context: All authenticated roles

- Response example:
```
{"data":{"id":1,"name":"User Name","email":"user@example.com","username":"user123"},"status":true,"message":"User profile retrieved successfully"}
```

## Reseller Account
### Reseller Signup
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/signup`
- Auth: Public
- Roles/context: New reseller
- Purpose: Register a new reseller account and trigger email verification.
- Parameters:
  - `first_name` (string, Mandatory, body): First name
  - `last_name` (string, Mandatory, body): Last name
  - `company_name` (string, Mandatory, body): Company name
  - `email` (string, Mandatory, body): Unique email address
  - `username` (string, Mandatory, body): Unique username
  - `phone` (string, Mandatory, body): Contact phone number
  - `currency_code` (string, Mandatory, body): 3-letter ISO currency code, e.g. USD or INR
  - `password` (string, Mandatory, body): Account password
  - `password_confirmation` (string, Mandatory, body): Must match password
  - `industry` (integer, Mandatory, body): Industry catalog ID
  - `telephony_provider` (integer, Mandatory, body): Telephony provider catalog ID
  - `expected_call_volume` (integer, Mandatory, body): Expected call volume catalog ID
- Rules:
  - Verification follows project.email_verification.method: OTP (default) or verification link.
  - Signup does not return a Bearer token. Verify email first, then log in.
  - industry, telephony_provider, and expected_call_volume are integer IDs from VoiceLink catalog lookups. The catalog/list endpoints for these values are not specified in the supplied source material — confirm the correct lookup endpoint before building a signup form.
- Request example:
```
{"email":"john@acme.com","phone":"+919876543210","password":"Secret@123","username":"johndoe","last_name":"Doe","first_name":"John","company_name":"Acme Telecom","currency_code":"USD","password_confirmation":"Secret@123","industry":3,"telephony_provider":2,"expected_call_volume":4}
```
- Response example:
```
{"data":{"user":{"id":10,"name":"John Doe","email":"john@acme.com","username":"johndoe"},"message":"Registration successful! We have emailed you a verification code. Submit it to /api/v1/auth/verify-otp to activate your account."},"status":true,"message":"Registration successful! We have emailed you a verification code. Submit it to /api/v1/auth/verify-otp to activate your account."}
```

## Client Management
### Create Client
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/client/create`
- Auth: Bearer
- Roles/context: Reseller
- Purpose: Create a client under the authenticated reseller.
- Parameters:
  - `first_name` (string, Mandatory, body): Client first name
  - `last_name` (string, Mandatory, body): Client last name
  - `username` (string, Mandatory, body): Unique username
  - `email` (string, Mandatory, body): Unique email
  - `phone` (string, Optional, body): Contact phone number
  - `password` (string, Mandatory, body): Password, minimum 8 characters
  - `is_active` (integer, Optional, body): 1=active, 0=inactive; default 1
  - `channel_count` (integer, Mandatory, body): Channels to allocate, from 1 to reseller availability
  - `plan_type` (string, Conditional, body): Required if reseller plan is Unlimited; unlimited or limited
  - `negative_threshold` (numeric, Mandatory, body): ≤0 and ≥ reseller threshold
  - `pulse_seconds` (integer, Conditional, body): Required for Limited client plan
  - `inbound_rate` (numeric, Conditional, body): Required for Limited client plan
  - `outbound_rate` (numeric, Conditional, body): Required for Limited client plan
  - `wallet_balance` (numeric, Optional, body): Initial balance from reseller wallet; ignored for postpaid reseller
  - `wallet_bypass` (integer, Optional, body): 0 or 1; when 1 billing debits reseller wallet and pricing mirrors reseller plan
- Rules:
  - DID mapping is separate: POST /reseller/client/map-did.
  - Client inherits reseller billing mode. For postpaid resellers wallet_balance is ignored.
  - If reseller has an unlimited plan, they can choose client plan_type.
- Request example:
```
{"email":"jane@example.com","phone":"9876543210","password":"Secret@123","username":"janesmith","is_active":1,"last_name":"Smith","first_name":"Jane","inbound_rate":0.5,"channel_count":5,"outbound_rate":0.8,"pulse_seconds":60,"wallet_bypass":0,"wallet_balance":100,"negative_threshold":-500}
```
- Response example:
```
{"data":{"client_id":101},"status":true,"message":"Client created successfully. Verification email sent."}
```

### Update Client
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/client/update/{client_id}`
- Auth: Bearer
- Roles/context: Reseller
- Purpose: Update profile, pricing, wallet threshold and channel allocation for a client owned by the reseller.

  - `first_name` (string, Mandatory, body): Client first name
  - `last_name` (string, Mandatory, body): Client last name
  - `username` (string, Mandatory, body): Unique username
  - `email` (string, Mandatory, body): Unique email
  - `phone` (string, Optional, body): Contact phone
  - `password` (string, Optional, body): New password; omit to keep current
  - `is_active` (integer, Mandatory, body): 1=active, 0=inactive
  - `channel_count` (integer, Mandatory, body): Channel allocation
  - `plan_type` (string, Optional, body): For unlimited reseller plan: unlimited or limited
  - `negative_threshold` (numeric, Mandatory, body): ≤0 and ≥ reseller threshold
  - `pulse_seconds` (integer, Conditional, body): Required for Limited plan
  - `inbound_rate` (numeric, Conditional, body): Required for Limited plan

- Rules:

### Map DID to Client
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/client/map-did`
- Auth: Bearer
- Roles/context: Reseller
- Purpose: Assign an available reseller DID to a client.
- Parameters:
  - `client_id` (integer, Mandatory, body): Client ID
  - `did_id` (integer, Mandatory, body): Available DID ID
  - `call_recording` (integer, Mandatory, body): 0=disabled, 1=enabled
  - `user_status` (integer, Mandatory, body): 2=assigned, 4=inactive
  - `user_expiry_date` (string, Optional, body): YYYY-MM-DD; cannot exceed DID expiry; defaults to DID expiry
  - `description` (string, Optional, body): Mapping notes
- Rules:
  - DID must belong to the authenticated reseller and be available.
  - Client auto-renew is enabled by default but is forced to 0 server-side unless the active reseller purchase has auto_renew=1.
- Request example:
```
{"did_id":5,"client_id":101,"description":"Primary inbound DID","user_status":2,"call_recording":0,"user_expiry_date":"2026-12-31"}
```
- Response example:
```
{"data":{"did_id":5,"client_id":101,"did_number":"9876543210"},"status":true,"message":"DID mapped to client successfully."}
```

### Allocate Wallet Balance to Client
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/client/allocate-wallet/{client_id}`
- Auth: Bearer
- Roles/context: Reseller
- Purpose: Transfer balance from reseller wallet to a client wallet.
- Parameters:
  - `client_id` (integer, Mandatory, path): Receiving client ID
  - `amount` (numeric, Mandatory, body): Amount, minimum 0.01
  - `description` (string, Mandatory, body): 3-500 character transaction note
- Rules:
  - Client must belong to the reseller.
  - reseller_balance - amount must be >= reseller negative_threshold.
  - Creates a DEBIT on reseller wallet and matching CREDIT on client wallet; both transactions are recorded.
- Request example:
```
{"amount":500,"description":"Initial wallet top-up for client onboarding"}
```
- Response example:
```
{"data":{"client_id":101,"allocated_amount":500,"client_balance_after":500,"reseller_balance_after":1000},"status":true,"message":"Wallet balance allocated successfully."}
```

## KYC
### KYC Status
- Method: `GET`
- Endpoint: `https://app.voicelink.co.in/api/v1/reseller/kyc/status`
- Auth: Bearer
- Roles/context: Reseller; optionally on behalf of owned client
- Purpose: Return current KYC progress and current/latest document state.
- Parameters:
  - `client_id` (integer, Optional, query): Owned client ID to inspect
- Rules:
  - Omit client_id for reseller KYC.
  - documents reports the current/latest document per type.
  - is_complete stays false until every required document is uploaded.

## Outbound Calling
### Add Outbound Lead
- Method: `POST`
- Endpoint: `https://app.voicelink.co.in/api/v1/add_lead`
- Auth: Bearer
- Roles/context: User with valid DID/outbound WebSocket routing
- Purpose: Create one or more outbound call leads and push them to the outbound queue.

  - `did_number` (string, Mandatory, body): Single DID to call from; validated once for all leads
  - `customer_number` (string, Conditional, body): 10-digit destination number when leads array is not provided
  - `leads` (array, Conditional, body): Bulk leads; required when customer_number not provided
  - `leads[].customer_number` (string, Mandatory per item, body): 10-digit destination number
  - `leads[].custom_parameters` (string, Optional, body): Valid JSON string; preserved if parseable

  - `custom_parameters` (string, Optional, body): Legacy single-lead JSON string only
  - `websocket_url` (string, Optional, body): Valid URL override for all leads
  - `webhook_url` (string, Optional, body): Valid URL override for all leads
  - `call_limit` (integer, Optional, body): Maximum call limit for all leads

## Unresolved items — do not guess
- Outbound routing values: API descriptions say outbound supports 2=SIP Trunk, 3=WebSocket Bot, 4=Only Answer and Mobile is invalid, but List Routing / Purchased DID sample responses show for_outbound_call=1 with label Mobile.
- Request-required DID series wording differs across supplied descriptions: some say 140/160, others 140/180. Use GET /reseller/did-types at runtime and confirm catalog naming.
- Create WebSocket Bot: prose says reseller client_id is optional, parameter table says mandatory. Confirm before strict validation.
- Create/Confirm purchase says auto-renew is mandatory for active purchases; renewal guards and DID release may force it off server-side. Documented here as a server-enforced exception, not a user toggle.
- Update Client wallet_balance semantics are not explicit (replacement vs increment). Use allocate-wallet for explicit balance transfer.
- KYC Final Submit definition contains no client_id parameter even though earlier KYC steps support reseller-on-behalf-of-client. Confirm how client KYC final submission is performed.
